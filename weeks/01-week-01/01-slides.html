Distributed systems

A distributed system is a collection of independent computers that appears to its users as a single coherent system. These computers, often referred to as nodes, work together to achieve a common goal, coordinating their activities by passing messages to one another.

The key characteristics of a distributed system include:

  • Concurrency: Multiple components operate simultaneously.
  • No Global Clock: Each component has its own clock, and there’s no single, synchronized global time.
  • Independent Failures: Components can fail independently without necessarily bringing down the entire system.
  • Transparency: Users perceive the system as a single entity, unaware of the underlying distribution of components.

Examples of distributed systems range from simple client-server applications to complex cloud computing platforms, peer-to-peer networks, and blockchain technologies. They are designed to offer advantages like scalability, fault tolerance, and increased performance by distributing workloads across multiple machines.

Multi-tier architectures

A multi-tier architecture, also known as an n-tier architecture, is a client-server architecture in which the presentation, application processing, and data management functions are logically separated. This separation allows for greater flexibility, scalability, and maintainability compared to a monolithic or two-tier architecture.

The most common multi-tier architecture is the three-tier architecture, which typically consists of:

  • Presentation Tier (Client Tier): This is the top-most level of the application, providing the user interface and communicating with the application tier. It can be a web browser, a desktop application, or a mobile app. Its primary function is to display information to the user and send user input to the next tier.
  • Application Tier (Logic Tier/Middle Tier): This tier contains the business logic and application processing. It acts as an intermediary between the presentation tier and the data tier, processing requests from the presentation tier, performing necessary computations, and interacting with the data tier to retrieve or store data. This tier often includes application servers, web servers, and message queues.
  • Data Tier (Database Tier): This is the lowest level, responsible for storing and managing the application’s data. It typically consists of database servers (relational or NoSQL) and data storage mechanisms. The application tier accesses this tier to perform CRUD (Create, Read, Update, Delete) operations on the data.

The benefits of a multi-tier architecture include:

  • Scalability: Each tier can be scaled independently based on demand. For example, if the application logic is heavily used, you can add more application servers without affecting the database.
  • Flexibility: Different technologies can be used for each tier, allowing developers to choose the best tools for specific tasks.
  • Maintainability: Changes in one tier have minimal impact on other tiers, simplifying development and maintenance.
  • Security: By separating the tiers, you can implement different security measures at each level, enhancing overall system security.
  • Reusability: Components within each tier can often be reused across different applications.

Each module begins with an introduction to the key questions and decisions an architect must consider when building out the relevant layer of their cloud architecture for these common patterns. There is a student guide for each lecture module and videos that reinforce the key concepts in each module.The labs in the course will give you the opportunity to apply your learning in each module through a hands-on AWS environment. Guided labs provide you with step-by-step instructions to help you gain experience in creating and configuring AWS resources in the different AWS service areas. The challenge (café ) labs contain sections that do not provide full click-level guidance or detailed step-by-step instructions. Instead, you are challenged to apply the skills you gained from the guided labs and the concepts presented in the lectures.

The AWS Academy Cloud Architecting Capstone is an additional lab experience where you can apply your learning without detailed guidance. The capstone is delivered through the same lab environment as the other labs, but the environment for the capstone is long lived. This means you can work on the lab over multiple days and pick up where you left off.

Recorded demonstrations are included in the course to illustrate some topics. These videos are included in your module materials, and your student guide includes introductory slides to indicate where the demonstrations fit in the lecture.

Your instructor might include instructor-led activities to complement the lecture. Introductory slides are included in your student guide. Additional information and materials for each activity will be provided as needed based on the activity.

Throughout the course, you will have opportunities to check your understanding of the materials presented. Each module, except the first and last modules, includes a 10-question knowledge check and a sample exam question for discussion. The course also includes a 25-question assessment that incorporates content from across the course. You can retry both the knowledge checks and the course assessment as many times as needed.
